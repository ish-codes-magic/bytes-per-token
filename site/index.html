What each technique did to the cost of a token

Stock vLLM in BF16, then one technique per bar. A hatched bar is a step that made serving dearer. The last bar is the best stack that was measured, when it is not the full one.

Findings

    "×" is output tokens per second over stock vLLM in BF16 on the same GPU and workload. These are better configurations of vLLM for a workload, not a faster engine than vLLM.

    Every server on one workload

    All measured configurations, as a multiple of the stock server. A label is the letters that are on: w FP8 weights, a INT4 weights, k FP8 KV cache, p prefix caching, s speculative decoding. f (FlashInfer on a BF16 cache) and g (piecewise CUDA graphs only) exist only on control servers.

    Do two techniques' gains multiply?

    Combined gain ÷ the product of the two gains alone. 1 means they multiply, below 1 they compete for the same slack, above 1 each makes the other more useful. Qwen3-1.7B.

    The pair that collides: a step that waits for its host

    With an FP8 KV cache and speculation together, vLLM 0.30 on this GPU cannot replay a decode pass as one CUDA graph. It falls back to piecewise graphs, Python runs between every layer, and the GPU waits. Each pair of bars is a server on piecewise graphs next to the closest server that kept its full graph.

    A step takes about max(what the GPU needs, what the host needs). Where the GPU already needs longer, nothing changes, which is why the first control server showed no loss.

    A model that had to predict it

    The serving model is built from the model's sizes, the GPU's measured ceilings and a few constants fitted on earlier milestones. Its predictions for every planned server were committed before any ran.

    Long-context correctness

    Needle in a haystack: a secret number hidden at a depth in a prompt of a given length. Each cell is the share of three secrets that came back. Lossy KV-cache techniques fail here first.

    Where drafting is easy

    Generated text with each token colored by who wrote it: drafted and accepted, or written by the target model. Boilerplate and copied text draft well; reasoning steps do not.
